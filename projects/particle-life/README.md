# Particle Life

An independent six-group particle simulation using its existing cdnjs **p5.js 1.4.0** dependency. Open [index.html](./index.html) through a local static HTTP server. The page uses the shared [page shell](../../assets/js/project-shell.js), [stylesheet](../../assets/css/style.css), and [page controller](../../assets/js/project-page.js), with project-specific matrix and brush wiring in [controlPanel.js](./controlPanel.js). No dependency or build tooling has been added; the bundled p5.js and sound files remain unchanged and are not newly loaded.

## Shared page

This is the complex **stacked** reference for the [shell contract](../_template/README.md#shared-shell-contract). Common wrappers, navigation, form, headings, status, reset/restart buttons, and source footer come from the single shared shell. This project's HTML supplies the intro, actual canvas host, disabled native controls fieldset, complete matrix markup, extra action buttons, help, and source-linked Next Steps. Background is omitted so the shared empty placeholder appears.

The shell mounts before project setup and moves the original nodes. Matrix controls are then generated by the existing project code before adapter connection. Matrix mapping, nested control groups, both regeneration actions, keyboard handling, defaults, and simulation logic remain project-specific. Generic page layout comes from the shared stacked variant; project CSS handles only the internal complex panel/matrix. Shared structural changes apply on reload without recopying this page.

## Preserved controls and actions

The original controls were inventoried before migration:

| Control or action | Default / range | Behavior |
| --- | --- | --- |
| Full interaction matrix | 6 rows x 6 columns; each entry from -1 to +1 | All 36 directed interactions update live, including the diagonal |
| Initial matrix | Diagonal +1; off-diagonal entries independently random in [-1, 1) | The simulation uses native slider precision, not the two-decimal display |
| Matrix keyboard editing | + / - changes the focused entry by 0.1, clamped to [-1, 1] | Preserved; arrow keys now also use 0.1 steps, and native sliders permit pointer/touch adjustment |
| Regenerate Matrix | All 36 entries independently random in [-1, 1), including the diagonal | Updates interactions immediately without replacing particles or brush settings |
| Regenerate All Cells | 100 randomly positioned cells in random groups | Replaces the population without changing any control or matrix entry |
| New-cell color | Random; Red, Green, Blue, Yellow, Purple, Orange | Applies to mouse-created cells only; Random chooses each cell's group independently |
| Cells per mouse press | 10; integer range 1-30 | Live creation count, not a population limit; has no effect on deletion or regeneration |
| Brush radius | 50 logical px; integer range 0-100 | Live radius for creation and deletion |
| Mouse mode | Create; Create / Delete | Press strictly inside the canvas to add the selected count or delete all cells strictly inside the radius |
| FPS and cell count | Live canvas overlay | Retained |

Creation retains the original random angle and random distance distribution within the brush. Deletion ignores the color and count settings. Radius zero creates at the press position and deletes nothing. There is no continuous drag painting, custom canvas keyboard control, or keyboard equivalent for canvas creation/deletion. Native controls support Tab/Shift+Tab, sliders and radio arrow keys, select keyboard navigation, and button activation. Matrix sliders additionally retain the original + / - shortcuts.

### Matrix direction and group identity

`connectionStrengthMatrix[row][column]` controls the acceleration of a cell in the **row** group in response to a neighboring cell in the **column** group, as used by [Cell.js](./Cell.js). Entries are not mirrored or transposed. Positive values attract and negative values repel in the existing force curve; close-range repulsion remains even for zero or positive entries. No force curve, speed, friction, wrapping, spatial-index behavior, or particle update ordering has changed.

The original group order and its inconsistent names/colors are deliberately preserved rather than silently remapped:

| Displayed group number | Internal index | Legacy selector name | Matrix marker | Rendered particle |
| --- | --- | --- | --- | --- |
| 1 | 0 | Red | Red | Red |
| 2 | 1 | Green | Green | Green |
| 3 | 2 | Blue | Blue | Blue |
| 4 | 3 | Yellow | Yellow | Yellow |
| 5 | 4 | Purple | Magenta | Cyan |
| 6 | 5 | Orange | Cyan | Magenta |

Numbered row and column headers, individual accessible slider names, and a visible explanation make the mapping explicit. Interaction-value markers retain the red-to-green scale; group identity does not depend on those markers.

## Adapter and reset behavior

The documented [adapter contract](../_template/README.md#control-to-simulation-contract) is connected once from [setup](./sketch.js). It receives `newCellColor` (string), `newCellCount` and `brushRadius` (numbers), `mouseMode` (string), and 36 numeric keys named `interaction_0_0` through `interaction_5_5`.

- `applyControlSettings(settings)` applies all settings live and formats matrix outputs. It does not restart the population.
- Restart Simulation recreates 100 random cells and retains all current controls, including every matrix entry.
- Reset Everything uses native form reset, then synchronizes the restored settings and outputs and restarts. A direct `form.reset()` follows the same path. Neither action reloads.
- Since the original initial matrix is random, its values are sampled once per page visit and stored at native slider precision as each slider's HTML default before connection. Reset restores that exact initial control matrix, including diagonal +1, rather than drawing a different matrix. Browser numeric serialization can differ from the original sample by floating-point epsilon; values are never rounded to the two-decimal display.
- Regenerate Matrix changes only current slider values, not their defaults, and dispatches a normal form input event. It does not replace the controls captured by the shared controller.
- All simulation controls remain disabled until initialization, initial settings, and restart succeed. Initialization errors remain visible; no success fallback is used.

## Canvas sizing

This project uses **fixed logical dimensions**, defaulting to **1000 x 600 (5:3)**, not Bouncing Ball's responsive logical resizing. The size is defined only by `createCanvas(1000, 600)` in [sketch.js](./sketch.js). The p5 renderer is passed as `canvas` to `ProjectPage.connect()`, which derives the host's maximum width and aspect ratio from its logical dimensions, independently of pixel density. Change only the `createCanvas()` arguments to change the size or ratio; no HTML sizing values need updating. Shared CSS displays the canvas at its natural logical size when space permits, or uniformly scales it down, never up, to fit its host. No resize observer or `resizeCanvas` call is added: interaction distances, brush units, spatial subdivisions, physics, and wrapping retain their original coordinate system and state during layout changes. Pointer mapping must be checked with the existing p5.js version at the scaled display size.

The full matrix is a semantic table with native labeled range inputs. Only the table's focusable scroll region scrolls horizontally on narrow screens; affected-group row headers stay visible while scrolling, and the page itself should not overflow. The controls are arranged below the canvas so the matrix is not squeezed into the template's small sidebar.

## Verification

There is no build or automated test framework. Serve locally under a repository URL prefix as well as normal static hosting, and check:

- Script syntax, original dependency loading, local assets, exact-case links, both navigation links, and console/network errors.
- All 36 matrix controls, asymmetric row/column mapping, diagonal entries, randomization, full-precision values, two-decimal outputs, keyboard bounds, and live updates without population replacement.
- Live color/count/radius/mode changes; mouse creation/deletion at desktop and scaled mobile sizes; unchanged particle state and fixed logical dimensions during resizing.
- Regenerate All Cells, repeated Restart Simulation with every value retained, Reset Everything restoring every native default/output, and direct `form.reset()`.
- Desktop/mobile layout, matrix scrolling and focus visibility, no document overflow, native keyboard navigation/activation, and disabled controls when the adapter is unavailable.

Local validation in the integrated Chromium browser covered 1440, 1024, 390, and 320 px viewport widths under `/p5js_simulations/`: all 36 live mappings and actual force directions, all 36 keyboard-focus positions at every width, outputs, matrix randomization, both population actions, full reset and direct form reset, desktop/mobile mouse coordinates, fixed-canvas state retention, native controls, and local assets/source links. These behaviors were rechecked after conversion to the shared shell, including native matrix touch input and unavailable-script/JavaScript-disabled fallback states. A shared-script-only fixture verified global block/button relocation and node/default/listener preservation without editing project HTML; see the [reference validation](../_template/README.md#shared-shell-reference-validation). Scripts were syntax-checked with the browser's JavaScript parser. The GitHub project-source URL returned HTTP 200. Normal page loading and animation produced no console errors or failed network requests.

### Remaining limitations

- CDN availability remains required; the original p5.js 1.4.0 dependency is unchanged.
- Chromium touch emulation confirmed that native matrix touch input updates the simulation. It also exposed the existing p5.js canvas touch fallback plus compatibility mouse event: one tap can create cells twice (for example, six cells with a count of three). This legacy behavior is disclosed in How to Use, not silently changed as part of the page migration. Use a mouse for predictable per-press counts.
- Validation uses browser viewport/touch emulation, not physical mobile devices or a cross-browser suite. Native control presentation can vary.
