# Ant Pheromone

This is the original p5.js ant-foraging simulation, integrated into the portfolio page without changing its foraging, movement, pheromone, or obstacle algorithms. Ants wander, collect food, and return it to their anthill; food returned to the hill can fund reproduction. The ants leave discrete wander and return pheromones that other ants may see and follow.

## Preserved baseline

The pristine defaults are in [simSettings.json](./simSettings.json). Each restart makes a fresh deep copy, changing only the two page controls.

| Setting | Original default and behavior |
| --- | --- |
| Logical canvas | Fixed at 600 x 600. It scales down uniformly for smaller layouts; simulation coordinates do not resize. |
| Simulation speed | 1 simulation update per rendered frame. It is an update count, not a wall-clock speed guarantee. |
| Initial skipped updates | 15. The existing loop compensates for these updates by decrementing its loop index, then runs the ordinary updates for that frame. At speed 1 the first draw callback therefore performs 15 warm-up updates plus 1 ordinary update. At speed 0 the warm-up remains pending. |
| Pheromone display | Enabled (`showPheromones: 1`). This setting controls rendering only. |
| Anthill | One at `(150, 150)`, size 100, RGB `(200, 100, 100)`, with 20 initial ants and 0 stored food. |
| Ant properties | Size 15; speed 2; steering strength 0.4; hit-box radius 20; field-of-view setting 1.5; configured view distance 150. The actual `isSeen()` distance check uses half that value (75, plus half an object's radius). |
| Wandering | `wanderAnywayRate: 0.001`, cooldown 1, and steering sensitivity 0.1. |
| Food | Three piles, each initially 100 units: `(200, 400)`, `(550, 100)`, and `(500, 280)`. Their RGB color is `(50, 200, 50)`. |
| Obstacles | Five configured rectangles in RGB `(50, 200, 200)`: `(300, 10, 20, 200)`, `(80, 300, 240, 20)`, `(300, 320, 20, 130)`, `(390, 180, 20, 170)`, and `(410, 180, 130, 20)`. Four additional border rectangles are generated by the field. |
| Pheromone emission | Anthill ticker interval 50 simulation updates. At each interval, an ant emits when it has seen the hill within the configured recent-visibility threshold or is carrying food. |
| Pheromone lifetime | Base 200 updates; wander lifetime multiplier 5 (1,000 updates) and return multiplier 1 (200 updates). Pheromones age during simulation updates and are removed at expiry. |
| Pheromone display sampling | `traceRate: 0.9` gives each pheromone a 90% chance of being drawn. It is not the emission interval or rate. |

Additional configured values include the ant's `traceRate: 0`, pheromone size 10, and `maxAntHillLastSeen: 450`. The JSON also contains `antCost: 10`, while the existing `AntHill` constructor currently hardcodes the same reproduction cost. Reproduction consumes 10 stored food units for each new ant; this cost is not a page control.

The existing pheromone-following selection is also preserved: ants carrying food consider wander-type pheromones, while ants not carrying food consider return-type pheromones. Visible marks are sampled for display independently of whether pheromones can be sensed or followed.

## Controls and actions

| Control or action | Type, constraint, and mapping | Timing |
| --- | --- | --- |
| Simulation speed | Native number input; integer, minimum 0, step 1, no maximum. Maps to `simSettings.json`'s `simSpeed`. Empty, non-finite, negative, and fractional input is rejected with a visible validation message and is not applied. | Live; 0 pauses model updates while drawing and controls remain usable. |
| Show pheromones | Native checkbox, default derived from `showPheromones`. | Live; affects drawing only, not creation, sensing, following, or lifetime updates. |
| Restart Simulation | Shared page button. | Recreates the configured anthill, initial ants, initial food, and obstacles using current control values; resets counters and pheromone/warm-up state without changing the controls. |
| Reset Everything | Shared native reset button. | Restores defaults from the pristine loaded configuration and restarts. Calling the native form reset directly does the same. |

Keyboard shortcuts work only while the simulation target has keyboard focus. Tab to the canvas or click it to focus it; controls and buttons keep their ordinary keyboard behavior.

- **D:** add 1 when the current speed is 4 or less; otherwise add 10. For example, 4 → 5 → 15 → 25.
- **A:** subtract 10, retaining the original lower bound of 0.
- **R:** set the skipped-update counter to the configured initial skip value minus 1,000. With the default this is -985. At speed 1, the callback performs 1,000 compensated fast-forward updates and then 1 ordinary update. At speed `N > 0`, it performs those 1,000 updates plus the ordinary `N` updates in the same draw callback. At speed 0 the request remains pending until updates resume. This is not a colony restart; a large loop can monopolize a draw callback.
- **Canvas click:** add one food pile of 30 units at the pointer position, only when the click targets a point inside the canvas. Scaled-canvas coordinates are mapped by p5.js 1.4.0 to the unchanged logical canvas. A touch tap is a single click; there is no drag-to-paint behavior.
- **Ant hover:** show the original inspection overlay, including purpose, pheromone count, time since seeing the anthill, and avoidance state. There is no keyboard equivalent for this mouse-only inspection.

Speed is updates per rendered frame, not guaranteed wall-clock acceleration. It remains uncapped to preserve the original shortcuts and behavior. High speeds, additional ants, and many pheromones increase computational cost.

## Dependencies and running

The original HTML referenced p5.js 1.4.0 from the CDN, and the bundled [p5.js](./p5.js) header also identifies version 1.4.0. The project uses the bundled copy at that version. Inspection found no p5.sound API use, so its script reference and unused bundled add-on were removed. The configuration and [ant sprite](./ant.png) load in p5's preload phase before the adapter connects; loading or initialization errors are reported visibly and to the console, with controls left disabled.

Serve the repository over HTTP, for example with VS Code Live Server, then copy its HTTP project URL into Edge. Do not open the page as `file:///...` or weaken browser security settings. All project and shared-asset paths are relative so the page also works beneath the GitHub Pages repository prefix.

## Planning notes and known limitations

The original [planning notes](./feladatok.txt) are preserved in Hungarian. In the older list, the hierarchy notes, placing anthills under the field/map, and creating pheromones are marked complete ([lines 19-24 and 32-37](./feladatok.txt#L19-L37)). The current implementation also has simulation-level food handling in [`Simulation.foodHandling()`](./simulation.js#L32) and anthill-level pheromone creation/storage in [`AntHill.update()`](./antHill.js#L17). Those are current behavior, not unfinished integration work.

Whether to move more non-interaction updates into `Simulation` and whether to reorganize all settings further around the hierarchy remain open design questions from [lines 26-31](./feladatok.txt#L26-L31). The current update order is field/anthill updates, simulation-level food handling, pheromone sensing, obstacle handling, then simulation-step and diagnostic updates.

Obstacle handling is deliberately unchanged. The notes report that multiple obstacles meeting can confuse ants, dynamic `pointsToAvoid` experiments did not solve it and can leave ants stuck, and edge avoidance is unreliable; projecting an ant position onto an edge is only a suggestion ([lines 2-6](./feladatok.txt#L2-L6)). The current avoidance calculation explicitly says it only works for non-diagonal rectangular obstacles ([`obstacle.js`, line 75](./obstacle.js#L75)). These limitations are not route-planning guarantees or plans implemented by this integration.

Commented-out experiments and ordinary explanatory comments in project source files are not treated as active behavior or new plans. TODOs in the third-party p5.js bundle are not project TODOs. The page's Background and References section is intentionally empty.

The model uses local visibility, wandering, and discrete pheromone marks; it has no pathfinding or diffusion grid and does not guarantee discovery of food, a route, or a stable trail within a fixed time. The existing warm-up and R fast-forward loop can block rendering while it runs.
