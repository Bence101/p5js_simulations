Self-Driving Car

Neural-network cars evolve through fitness-weighted selection and mutation while following ordered checkpoints on a bundled PNG track. The best car's brain survives unchanged into the next generation; manual driving inputs can influence the cars alongside the AI.

  • Open the page over HTTP: use VS Code Live Server or another local HTTP server, then copy its http:// address into Edge or your preferred browser. Double-clicking the HTML file opens a file:// address, where browser security blocks the required image loading.
  • Driving keys: Tab to the simulation or click/tap its canvas to focus it. Left/right arrows add steering, up/down arrows add acceleration/deceleration, and Space assigns zero speed. These inputs affect applicable cars, not a selected player car. The AI executes afterward in the same update, so Space is not a reliable pause and manual input never disables AI.
  • Canvas pointer actions: clicking or tapping only focuses the simulation. There are no canvas editing or mouse-based simulation actions; dragging does not modify the track or add objects.
  • Native controls: Tab/Shift+Tab moves focus, arrow keys operate sliders and the number input, Space toggles the checkbox, and Enter/Space activates buttons. Driving keys do not steer while these controls have focus.
  • Restart Simulation: discards learned state and starts a fresh population with current settings, including the pending population size. All control values stay unchanged; a stopped run resumes.
  • Reset Everything: restores code-provided defaults and restarts learning. A direct native form reset has the same behavior.

Evolution continues automatically while the run is active. Speed ranges from 1 to 10 updates per rendered frame in steps of 1 (default 1). Mutation amplitude ranges from 0 to 1 in steps of 0.01 (default 0.2) and adds a uniform random shift between the negative and positive amplitude to each offspring weight and bias. A zero amplitude still permits fitness-weighted selection, but adds no perturbation. Population size is a whole number from 1 to 100 (default 10); ancestor labels are enabled by default.

Generation numbering starts at 0. A generation ends when no unfinished car is alive or after 3000 updates. The run stops at generation 1000; use Restart Simulation to learn again. Fitness favors checkpoint progress and average speed. There is no crossover or NEAT, and no guaranteed number of generations to learn a successful route.

The retained call new NeuralNetwork(6, 4, 3, 4) is interpreted by this project's three-argument library as 6 inputs, 4 hidden nodes, and 3 outputs. The fourth argument is ignored: the AI can select left, right, or acceleration; the fourth deceleration branch is unreachable. This original behavior has not been redesigned.

The logical canvas remains fixed at 800 by 600; only its display scales down. Pixel-based sensing and collision checks are computationally expensive, especially above 10 cars. Background tabs may suspend animation. Generation skipping remains a source-only setting at 0 because its loop can block a frame.

Track workflow: the independent Image Creator can export a bitmap. This page consumes only its bundled PNG; the start position, heading, and ordered checkpoints are configured separately in init.js. There is no live authoring connection, runtime map editor, or import feature. See the project README for the full inventory and retained limitations.
