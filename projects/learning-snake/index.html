Learning Snake

A population of 300 neural-network agents learns to play Snake on 8×8 boards. Each generation, parents are chosen by fitness, recombined, and mutated to produce the next population. The canvas shows 49 randomly sampled agents playing at once, and a chart tracks the best score, average score, and average fitness of every finished generation.

Simulation speed

1 is the original speed: every agent moves once per animation frame. Higher values wait that many frames between steps, slowing the simulation without changing the learning algorithm.

  • Actions and shortcuts: change the speed slider, use Restart Simulation or Reset Everything, or use the original testing keys. With no control or link focused, Enter advances every agent in the current generation by one step. Left, Up, and Right each advance only the first agent by one step; the arrow direction is ignored because the agent's own neural network chooses the move. The shortcuts are ignored while a form control, button, or link has focus.
  • Animation frames per simulation step (1–30, default 1): applies immediately. At 1, each animation frame moves every agent once. At 2, a step happens every second frame, and so on. The end-of-generation evaluation uses the same timing.
  • Restart Simulation: discards the current population, starts generation 1 with 300 new random agents, clears the chart and readout, and chooses a new random sample of 49 agents to display. It keeps the current speed value.
  • Reset Everything: restores the speed to 1 frame per step and restarts the simulation as described above. It does not reload the page.
  • Canvas: the logical canvas stays 700×700 and scales down uniformly on smaller screens. It shows 49 of the 300 agents, sampled at random with replacement, so an agent can appear more than once. There are no mouse or touch controls on the canvas.
  • Generation chart: it appears below the Project Information section. The horizontal axis is the generation number. The left axis shows the best score and average score, which count apples eaten; the right axis shows average fitness. A text summary of the latest finished generation appears below the chart.
  • Native keyboard controls: use Tab and Shift+Tab to move between controls, the arrow keys for the slider, and Enter or Space for buttons.

These notes come from the original Hungarian source comments and ToDo.txt; they are translated here and have not been implemented as part of this page.

  • GUI: the original plan was to work out a GUI (snakeGame.js, line 13). This page only adds the speed control.
  • Reward shaping: add a penalty for taking too long to reach an apple. It should be proportionally large when there are few apples and fade as the snake eats more, for example with squared terms. In theory this pushes the snake to learn both left and right turns early instead of repeating a big-circle strategy (ToDo.txt, lines 1–3).
  • Last-resort idea: if learning stays poor, build a preference for turning in both directions into the reward function. The author considered this a last resort or speed test and felt it was partly cheating (ToDo.txt, line 8).
  • Direction and coordinate checks: the up/down directions may have a problem, and the rows/columns logic is not consistent everywhere. The note suggests using width and height consistently (ToDo.txt, lines 33–35).
  • Possible vision inputs: the notes list signed head-to-apple x/y distances, snake size relative to board size, and wall/body counts in surrounding x×x squares as candidate inputs. Convolution is marked as only an idea (ToDo.txt, lines 37–46). The current network uses 24 inputs: wall, tail, and apple distances in eight directions.
  • Code cleanup: add a doCrossover parameter (population.js, line 33); rename populationNotDone (population.js, line 11); refactor hadMultiDirection (snakeGame.js, line 244); and decide whether stepSinceLastApple belongs to the agent or the game (snakeGame.js, line 127).
  • Neural-network code: carry all improvements over to the NNVisual project (neuralNetwork.js, line 1); split predict into feedforward and prediction (line 19); and move cost functions into a separate class like the activation functions (lines 137 and 148).
  • Disclaimers: a 2022-10-16 note says that even after the apple-vision rework the snakes only reached 20–22 apples with an average of about 5 (ToDo.txt, lines 11–14). The population size note says larger populations should work but the display would show little of them (sketch.js, line 10), and the displayed sample is currently random (line 17). In neuralNetwork.js, getNNData is untested (line 162), randomizeData only works for initialization (line 214), calculateAccuracy only works for binary classification (line 234), and crossover has no schema check between networks (line 288).
